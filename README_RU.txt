WATCHTOGETHER — ОБНОВЛЕНИЕ 2.0

ЧТО В АРХИВЕ
- server.js
- package.json
- public/app.js
- public/index.html
- public/style.css
- render.yaml (пример настройки Render с FFmpeg и постоянным диском)

УСТАНОВКА
1. Сделай резервную копию текущего проекта.
2. В корне GitHub-репозитория замени server.js и package.json.
3. В папке public замени app.js, index.html и style.css.
4. Сохрани изменения и дождись нового Deploy на Render.
5. Для постоянного хранения файлов и комнат нужен Persistent Disk Render. Настрой DATA_DIR=/var/data и подключи диск к /var/data. Пример конфигурации есть в render.yaml. Само наличие файла render.yaml не подключает диск к уже существующему сервису автоматически — применить Blueprint или настроить диск в настройках Render нужно отдельно.
6. Для реального создания качеств видео 360p/480p/720p/1080p на сервере должны быть установлены ffmpeg и ffprobe. В render.yaml они устанавливаются командой apt-get. Без них будет доступен оригинал, а варианты качества не появятся.
7. После установки проверь адрес /api/health — должен вернуться JSON с ok:true.

ЧТО ДОБАВЛЕНО
- Комнаты и их коды сохраняются в rooms.json; участники могут вернуться с тем же session ID после перезагрузки сервера, если подключён постоянный диск.
- Временное отключение не удаляет участника сразу. Окно восстановления — 10 минут.
- Владелец может остановить видео для всех. Участник может отправить запрос владельцу; владелец принимает или отклоняет его.
- Владелец управляет воспроизведением и перемоткой; сервер проверяет права.
- Голосовой чат WebRTC, индикатор говорящего на основе уровня звука микрофона.
- Загрузка видео частями по 8 МБ. При обрыве можно выбрать тот же файл повторно: браузер использует сохранённый upload ID и пропускает уже загруженные части.
- Библиотека сохраняется на диске. Удаление/загрузка библиотеки защищены проверкой сессии владельца комнаты.
- FFmpeg создаёт варианты 360p/480p/720p/1080p только если исходник имеет достаточное разрешение. Список качеств обновляется в комнате; переключение качества передаёт выбранный вариант всем и сохраняет позицию воспроизведения.
- Видео вписывается в плеер без обрезки (contain); полноэкранная панель с микрофоном и выходом находится внутри плеера.
- Источники: YouTube, прямые MP4/WebM ссылки и страницы сторонних сайтов, которые разрешают iframe.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- Нельзя гарантировать воспроизведение фильма с любого сайта. Если сайт запрещает встраивание через CSP/X-Frame-Options, требует вход или использует защищённый DRM-поток, WatchTogether не сможет показать его плеер. Ограничения сайта не обходятся. Внешний iframe — это плеер сайта, и его внутреннее управление/таймлайн нельзя синхронизировать универсально. Полная синхронизация управления доступна для загруженных видео, прямых видеофайлов и YouTube.
- Для прямой ссылки на видео сервер/источник должен разрешать загрузку из браузера (CORS/доступность). Для удалённых прямых URL качество выбирается на стороне источника.
- Загрузка после закрытия браузера не продолжается в фоне. Уже загруженные части сохраняются на сервере; после повторного открытия нужно снова выбрать тот же исходный файл, чтобы браузер мог передать оставшиеся части.
- Постоянный диск Render обычно требует платного плана и имеет ограниченный объём. Не загружай файлы, на хранение которых у тебя нет прав.
- Качества FFmpeg создаются в фоне и расходуют CPU/диск. При нескольких больших загрузках обработка может занять время.
- Встроенные комнаты хранятся в одном процессе Node.js. Для горизонтального масштабирования нескольких экземпляров понадобится общая база данных и Socket.IO adapter (например Redis); это не включено.
- Встроенная голосовая связь лучше работает при настроенном TURN-сервере. STUN по умолчанию не гарантирует соединение во всех сетях. Можно задать TURN_URL, TURN_USERNAME, TURN_CREDENTIAL в Render Environment.

ПЕРЕМЕННЫЕ TURN (НЕОБЯЗАТЕЛЬНО)
TURN_URL=turn:your-server:3478
TURN_USERNAME=...
TURN_CREDENTIAL=...

ПРОВЕРКА
1. Открой сайт в двух браузерах/на двух устройствах.
2. Создай комнату в первом и войди по коду во втором.
3. Проверь чат, голос и индикатор говорящего.
4. Владелец добавляет YouTube или загружает файл; второй участник проверяет синхронизацию.
5. Участник нажимает «Попросить остановить», владелец принимает/отклоняет.
6. Обнови страницу и проверь восстановление комнаты.
7. Загрузи большой файл, прерви соединение, затем выбери тот же файл повторно для продолжения.
8. Для стороннего сайта проверь, что он действительно разрешает iframe. Некоторые сайты не откроются — это ограничение источника.

ПРИМЕЧАНИЕ
Это обновлённый комплект исходников, но он не проходил полноценное end-to-end тестирование на твоём Render и в реальной сети с двумя устройствами. Сначала сделай резервную копию. Не удаляй старые данные до проверки новой версии.


ДОПОЛНИТЕЛЬНО: КАТАЛОГ INTERNET ARCHIVE
- Владелец комнаты открывает вкладку «Каталог фильмов».
- Вводит название или ключевые слова и нажимает «Найти».
- В результатах можно просмотреть обложку, год, описание и сведения о правах, затем нажать «Выбрать фильм».
- WatchTogether получает метаданные выбранного материала и выбирает доступный MP4 или WebM. После этого видео запускается в общем плеере комнаты и синхронизируется обычными командами владельца.
- Если у конкретного материала нет подходящего файла для браузера, появится сообщение и можно выбрать другой фильм.
- Источник каталога: Internet Archive (archive.org). Это архив материалов, а не полный каталог современных кинотеатральных фильмов. Наличие записи не гарантирует, что видео можно воспроизвести в браузере или что права на него одинаковы во всех странах. Проверяй права на странице конкретного материала.
- Поиск выполняется через официальный Advanced Search API Internet Archive, сведения о файлах — через Metadata API.
